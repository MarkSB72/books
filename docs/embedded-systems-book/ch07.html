与外设通信

外设是处理器与之通信的、位于处理器核心之外的任何东西。外设的形状和大小各异。由于处理器核心可以直接访问处理器内部的存储器，存储器几乎不能算作外设（不过存储器也可能在芯片外部）。

那么，与外设通信的最佳方式是什么：UART、SPI、I2C，还是别的什么？我经常被问到这个问题。所以让我们谈谈为什么没有答案。我需要一整章来解释。

在本书中，我们已经探讨了处理器内部发生的事情。在你能构建一个系统之前，我们需要考虑其他组件中发生的事情。与其他组件通信是其中的起点。我想向你展示，在决定使用哪种通信方法或编写通信驱动程序时应该关注什么。

大多数情况下，你最终会使用处理器硬件抽象层（HAL）中的驱动程序。你需要根据外部设备的数据手册和处理器的用户手册来配置它。然而，当你遇到一种新的通信方式——一种没有现成驱动程序的通信方式时，这种方法就行不通了。所以，让我们来看看我们常用的协议和方法，以此作为识别新协议中重要部分的方式。

串行通信 从最广泛的定义来看，串行通信是一次一个比特地通过通信通路（通常是一根线，物理线）发送数据的过程。¹在这个定义下，甚至以太网也是一种串行通信形式。让我们缩小一下定义范围，说串行协议是可以通过通用同步/异步收发器（USART，发音为"use-art"）实现的东西。这可能对你帮助不大，对吧？让我定义一些术语，然后我们来看最常见的串行通信方法。

¹ 这与并行通信形成对比，在并行通信中，每个比特都有专用的通信通路。

UART（发音为"you-art"）实现了在设备和计算机之间连接串行电缆时的默认协议。

即使是高端互联网路由器通常也配有用于配置或调试的串口。串口不仅实现成本低，而且就像梅花螺丝刀一样：大多数人不知道他们看到的是什么。

UART（通用异步收发器）比 USART 少了一个 S，所以在继续之前，让我退一步谈谈术语。S 代表同步，意味着时钟是与数据分离的信号。异步通路有一个隐式时钟，通常使用起始位和停止位来指示通信何时发生（因此降低了带宽）。由于隐式时钟需要允许一定的时序误差，同步总线可以比异步总线以更快的速度运行。通常，时钟的生成者也控制总线，使其成为非对称通路。通常只有总线控制器才能发起数据传输。

考虑串口时的另一个重要因素是：你有两根线来通信（发送和接收），还是只有一根线（根据轮到谁说话来切换方向）。有两根线称为全双工；共用一根线称为半双工。I2C 和 1-Wire 总线是两种最流行的半双工协议。当然，半双工通信调试起来稍微复杂一些，因为你无法在示波器（或逻辑分析仪）上确定哪个芯片是字节的源。

外设数据手册中的时序图通常对让通信驱动程序正常工作至关重要。当你第一次调通驱动程序时，要做好准备花一些时间设置示波器，尝试重现那些时序图（以验证你的驱动程序）。关于数据手册和示波器的技巧，请参见第3章。

当遇到一种新的通信总线时，需要关注的事项包括： • 通信时钟是如何产生的？是异步的（所有参与方事先约定好）还是同步的（通过总线上的线显式传输）？如果是同步的，时钟发生器是否有其他特殊职责？ • 通信是对称的（任何人都可以说话）还是非对称的（只有总线控制器发起通信）？ • 是全双工（有足够的 I/O 使每个人都能发送数据）还是半双工（通过共享 I/O 轮流发送数据）？ • 它需要多少根硬件线？ • 是点对点还是点对多点？寻址是通过协议完成还是通过片选？ • 系统的最大吞吐量是多少？每秒可以传输多少数据比特？其中有多少是开销？ • 信号能传输多远？

这些问题的目的是弄清楚你使用该通信总线实现一个驱动程序需要多长时间。

许多处理器都附带有示例代码，特别是通信驱动方面的。有时这些代码非常优秀，但有时它只是一个让它跑起来的示例（而不是稳健地工作）。如果你把它整合到你的项目中，请务必审查这些代码。

暂时放下这些高层术语和通用问题，让我们来看看一些流行总线的行为。请记住，这仍然只是一个介绍。最终，你需要查阅你的数据手册来了解外设需要什么，以及你的处理器手册来了解如何提供它。

串行通信

TTL 串行

正如我们所见，"串行"这个词被过度使用，指代许多协议。即使是最常见的串行接口（系统与计算机之间的接口）也有好几个名字。我已经提到过 UART，它是处理器中实现此接口的部分。然而，它发出的是 TTL 电平的串行信号。根据定义，TTL（晶体管-晶体管逻辑）意味着0-5 V。然而，在实践中，它指的是你的处理器数字 I/O 的任何电压电平：0-5 V、0-3 V、0-1.8 V 等。

虽然可能还有其他信号（参见"RS-232 串行"），但最重要的信号是发送（TX）和接收（RX）。仅凭这两个信号，你就可以将嵌入式系统与计算机连接起来。注意，两个系统都有 TX 和 RX，因此需要交叉连接，将每个 TX 连接到另一侧的 RX。

TX 和 RX 不交叉是我见过的最常见的硬件问题。如果某个组件在通信总线上没有响应，请检查 TX 和 RX（或时钟和数据）线是否正确。

要从你的板子连接到计算机，你需要一根 USB 转串口电缆（有时称为 FTDI 电缆，以制造该电缆的公司命名）。务必选择一根 TTL 侧电压与你的处理器相匹配的电缆。

这种形式的串行通信位于 OSI 模型的物理层和数据链路层（稍后将在"通信的分层模型（OSI）"中详细介绍），

它没有内置的寻址方案，因此只能在两方之间建立通信（对称点对点通信）。

它使用隐式时钟（异步！），因此双方必须就波特率（每秒比特数）、奇偶校验、起始位和停止位的数量以及流控制达成一致。虽然流控制通常完全不使用，但可以通过硬件使用其他 UART 线，或通过软件使用 Xon/Xoff 协议来实现。"延伸阅读"提供了解释这些约定的资源。

要与处理器的调试串口通信，通常应选择8个数据位、无奇偶校验、1个停止位、无流控制。这通常缩写为 8N1，无流控。

波特率通常在 2,400 到 115,200 之间（虽然最高可达 921,600）。某些波特率非常流行：9,600、19,200 和 115,200。由于使用隐式时钟，你需要在两个设备（即你的处理器和计算机）上配置相同的波特率。

由于每个数据字节都要发送起始位和停止位，大多数串行连接的字节吞吐量大约等于其波特率除以10。如果你的波特率是每秒 19,200 比特，你的系统大约每秒能发送和接收 1,920 个字节。与此相比，标准 100 兆以太网（虽然 1 吉比特也很常见）根据协议不同，吞吐量约为每秒 11 兆字节。串行很慢。

RS-232 串行

RS-232 与 TTL 串行类似，只有电气变化，没有软件影响。串口过去指的是带有 DB-9 连接器的 RS-232 端口。信号是（+/– 12 V）。图7-2展示了嵌入式开发中串行电缆的常见用法。虽然 RS-232 定义了八个信号（加上地线），但最重要的是来自处理器的 TTL 电平发送和接收线。

然而，如果你要连接到蜂窝数据调制解调器或串口转以太网转换器，你可能还需要其他一些 UART 线来指示每个设备何时准备好接收数据（特别是用于硬件流控制的 RTS/CTS 握手）。尽管时钟是隐式的，你需要指定哪一侧是总线控制器，因为这些信号并不完全对称。在 RS-232 中，总线控制器（通常是你的计算机）是数据终端设备（DTE），另一侧是数据通信设备（DCE）。是的，几乎每种协议对类似的东西都有不同的名称。

RS-232 相对较高的电压（12 V！）意味着信号在衰减之前可以传输相当远的距离——使用普通串行（或零调制解调器）电缆可达50英尺（15米）。特殊电缆（低电容）可以将距离增加约20倍。

RS-232 似乎已经存在了永远那么久，并且继续被广泛使用。尽管随着新协议（以太网、USB 等）取代它，它的消亡经常被宣告，但 RS-232 不断回归，因为它在软件上易于实现，在硬件上实现成本低廉。

SPI RS-232 和 TTL 串行工作有一些缺点：约20%的比特流是开销；双方都必须知道设置（例如波特率和奇偶校验）；而且 RX/TX 交叉的要求很麻烦，因为哪根线是 RX（或 TX）取决于你的视角。

相反，我们可以使用 SPI，它使用四根线将处理器连接到 SPI 外设：

MISO（微入传出，原主入从出²）或 SDI（串行数据输入） 总线控制器的接收端，通常是你的微处理器。

MOSI（微出传入，原主出从入）或 SDO（串行数据输出） 总线控制器的发送端，通常是你的微处理器。

² 术语很重要。对控制器：principal、host、primary。对外设：agent、worker、subordinate、secondary。

SCK、CLK 或 SCLK（时钟） 由控制器产生；这是双方通信的时钟。

CS（片选）或 SS（传选，原从选） 每个外设一根线。由总线控制器产生，通常为低电平有效。

SPI 是一种同步的、非对称的协议，时钟由控制器提供。SPI 的一个奇特之处在于，控制器和外设在时钟运行时都必须发送数据，始终交换数据，即使其中一方没有什么重要信息要说。

有时控制器不需要发送命令，但它需要发送一个字节才能接收一个字节。0xFF 是当你想要强制外设发送数据时传统上发送的字节。这被称为"时钟输出"数据。

在 RS-232 的隐式时钟下，通信双方都需要一个相对精确的振荡器；否则，它们可能失去同步。由于控制器提供时钟，SPI 不需要任何一方拥有精密振荡器。控制器可能仍然有某种振荡器，但不需要那么精确，因此可以更便宜。

时钟速度可以很慢（几十 Hz）也可以很快（高达 100 MHz）。时钟速度就是波特率，而且没有任何开销，所以 8 MHz 的时钟可以达到 1 MB/秒，比 RS-232 快得多，并且在高速时钟下甚至可以与以太网相媲美。最后，时钟速度可以是你的处理器能产生的、以及特定外设能接收的任何速度。不需要试图精确运行在 8 MHz；运行在 8.1234 MHz 或 7.9876 MHz 是可以接受的。运行如此快时钟的另一面是它传输不远。SPI 信号通常不会离开电路板。

该协议定义了片选，因此多个外设通常可以共享单个 SPI 总线，只要每个外设有一根 CS 线。

请检查你的外设数据手册；并非所有外设都能在共享总线上良好协作。

SPI 驱动程序甚至比 RS-232 驱动程序更容易实现。唯一棘手的部分是确定你希望线上的数据在时钟沿上升还是下降时有效（时钟极性和相位）。你的外设数据手册会告诉你它需要什么，处理器手册会给你一些寄存器来配置它。

位敲打驱动程序

SPI 接口如此有序和有条理，以至于它经常被实现为位敲打（bit-bang）接口。位敲打驱动程序直接使用 I/O 线来完成通信接口的工作，而不是使用处理器的内置寄存器。老实说，你可以为任何串行接口创建位敲打驱动程序，但它消耗的处理能力远高于内置的处理器接口。然而，有时你的处理器没有实现所需通信方法的硬件接口，你就得自己做了。

要创建你自己的 SPI 接口： 1. 从三根未使用的 I/O 线和一个内置定时器开始。片选线的工作方式与处理器提供的接口相同，所以我这里不计算它。 2. 设置一个定时器以四倍于时钟速度的频率中断（因此，对于 2 MHz 的通信速率，需要 8 MHz）。四个中断各有用处： • 翻转 I/O 线 • 将输出位写入 MOSI • 翻转 I/O 线 • 从 MISO 读取输入位 3. 每八个比特（或32个中断），开始一个新的字节。

注意，每个完整的时钟周期你需要写一个比特并读一个比特。然而，外设数据手册可能会告诉你，安全读取的时间与安全写入的时间相差半个时钟周期，这就是为什么我们需要定时器以预期通信时钟频率的四倍中断。

总的来说，每次中断你不需要做太多事情，但你有大量的中断，这意味着大量的上下文切换。

I2C 和 TWI

I2C 代表集成电路间总线，发音为"eye-squared-see"或"eye-two-see"。I2C 有时被称为 TWI，即"两线接口"。与 SPI 一样，I2C 总线有一个提供时钟并启动交互的控制器。然而，与 SPI 不同的是，I2C 总线可以有多个控制器。控制器甚至可以切换角色，允许外设来驱动交互。

串行通信

I2C 是试图搞清楚用尽可能少的线连接一大堆东西的结果。它使用两根连接：SCL（串行时钟线）用于时钟，SDA（串行数据线）用于数据（通过同一根线双向传输，使这成为半双工协议）。

硬件设计的简单性是以软件复杂性为代价的。不仅如此，因为这是一个多点协议，允许多个外设（和多个控制器），它指定了一个地址方案，这使它超越了 OSI 第1层（物理层）和第2层（数据链路层），进入第3层（网络层）。另一方面，I2C 使用相当广泛，所以你应该能找到一些示例代码来帮助你实现驱动程序。

I2C 驱动程序（或处理器硬件）总是包含一个状态机来处理总线方向在控制器发送和外设发送之间切换的复杂性。控制器通过发送一个7位地址并指示是要从外设读取还是写入来开始通信。具有该地址的外设随后发送一个确认（ACK）。接下来，控制器向外设发送命令（或从外设读取），交互继续。当通信完成时，控制器发送一个停止位。

连接到总线上的组件数量受限于地址空间（以及总线的电容）。许多组件允许你使用上拉电阻设置地址的最后几位，这样你可以在总线上放置同一部件的多个实例。或者，某些组件有稍有不同的零件号，导致不同的 I2C 地址。

常见的 I2C 总线速度是 100 Kb/秒（标准模式）和 10 Kb/秒（低速模式）。它是同步的，所以控制器发送时钟，这些频率不需要精确。一些外设实现了更快的速度：400 Kb/s、1 Mb/s，甚至 3.4 Mb/s。³

虽然 I2C 总线内置了一些开销——总线仲裁和启动/停止位——但如果你在移动大量数据（例如从 ADC [模数转换器] 或 EEPROM 读取），这些开销在流量中所占的百分比就变得可以忽略不计了。因此，标准模式在 I2C 总线上可以达到 12.5 KB/s 的吞吐量。

I2C 通常不用于与远距离外设通信，但它在电缆使信号衰减过多之前可以传输几米（不过你可以使用收发器和特殊电缆来增加距离）。由于该协议只需要两根线连接多个外设，电缆可以只有四根线：SDA、SCL、电源和地。

³ 记住，"b" 表示比特，"B" 表示字节（几乎总是如此），所以从 Mb 转换为 MB，除以8。

1-Wire

I2C 实际上并没有赢得串行线最少奖；还有名称恰如其分的 1-Wire（单线）总线。它通过单根线提供低速数据通信和供电。（当然，你还需要地线。）它在概念上与 I2C 类似（控制器、仲裁、带状态机的软件驱动程序），但它有一个 16.3 Kb/s 的隐式时钟。虽然这是一个相当低的数据速率，但它可以用于更远的距离，最远可达 10 米（使用特殊电缆可达100米）。

与 I2C 一样，该总线可以与各种外设一起使用，包括存储器、传感器、ADC 和 DAC。除了简单的温度传感器，最常见的 1-Wire 实现是认证芯片。这些芯片用于认证系统中可更换部件的来源。例如，如果你在制造打印机墨盒（或任何形式的消耗品），并且想要阻止竞争对手制造兼容替代品，一个 1-Wire 安全认证芯片将强制你的消耗品在使用之前向你的固件发送正确的密码。

虽然你不能真的只用一根线与设备通信，但有些设备使用寄生供电，利用通信线作为电源，这样电缆只需要两根线（数据/电源和地）。

并行通信 并行通信意味着有多根 I/O 线，这样你可以同时向外设发送和接收多个比特。通过在总线上同时放置8位或16位数据，你可以非常快速地通信。并行总线的数据位几乎总是组合在单个 I/O 引脚组上。这样，你可以通过将数据字节写入 I/O 寄存器来设置所有位。如第4章所示，不是设置单个位：

P1OUT |= BIT2;

// IO1_2 高电平

你可以一次修改多个 I/O 线：

P1OUT |= data & 0xFF; // 将8位数据放到并行总线上：IO1_0 到 IO_7

并行接口往往使芯片更昂贵。I/O 线在硅片中占用空间，而硅片的尺寸与芯片制造成本成正比（尽管对于许多芯片来说，RAM 比 I/O 线消耗更多的硅片面积）。

并行接口往往保留给具有高数据吞吐量需求的东西：显示器和外部存储器，这些我们稍后会讨论的组件。一个 320×480 像素的小型彩色 LCD 每屏幕需要 450 KB（如果你更新整个屏幕的话，不过你通常不会这样做）。

串行通信

在至少 30 Hz 的刷新率下，你需要每秒移动约 13 MB（105.5 Mb/s），这比 SPI 能处理的速度更快。然而，使用8位宽的并行总线，每线的比特率下降到 13 Mb/s。数据分布在整条总线上，所以并行的线越多，吞吐量越高。

纯并行总线往往是半双工的，带有控制线来指示数据的方向（读和写线）以及总线是否连接到芯片（片选线）。控制线通常也是系统的时钟，所以一次写交互会如下所示： 1. 取消写控制线的断言。 2. 选择芯片。 3. 将并行总线设置为目标数据。 4. 断言写控制线。 5. 回到第2步，直到所有数据已传输完毕。 检查你的外设数据手册的时序，以确定你需要在这些步骤之间是否有延迟。总而言之，实现并行总线相当容易，与 SPI 驱动程序的难度相当，尽管调试稍微困难一些，因为有太多线需要查看。

注意，并行总线可以与其他协议（通常是 SPI）结合，这样你可以通过两个或四个 MOSI 数据引脚并行工作来发送更多数据。

如果你在设计时有多余的 I/O 线，将它们引到排针或测试点上。你可以将错误或事件代码写入 I/O 线，形成一个用于调试（和性能分析！）的并行总线。将这些线连接到逻辑分析仪上，以窥探你的系统在做什么（不会有串行输出带来的时序变化）。

双线和四线 SPI

如果你将并行总线与 SPI 总线交叉，会得到什么？传输数据更快的东西。

普通 SPI 有 MISO 和 MOSI 用于通信，而支持双线 SPI 总线的组件会在某些操作中将那些线都变成输入（或都变成输出），允许双倍的数据通过。当操作完成时，总线将返回正常的全双工操作。

使用四线 SPI 总线时，有四根引脚发送数据。其中两根引脚一开始是 MISO 和 MOSI，然后对于某些操作会变成四线并行总线，以比正常 SPI 快四倍的速度传输数据。

USB 前面提到的所有串行协议，如果你没有硬件（且你有足够的处理能力），都可以用位敲打实现。我不会对 USB 尝试这样做，因为它相当复杂，电气上涉及更多。它是一个异步系统，有隐式时钟，最多支持127个设备。根据版本不同，它可以是全双工或半双工。它始终是非对称的，不过通常这里的术语是主机和设备，而不是控制器和外设。

它速度也很快（1.5、12、480 或 4,000 Mb/s，取决于版本）。电缆可以是中等长度（五米），仍然保持信号完整性。USB 通过差分信号来管理高吞吐量和较长电缆（这需要两倍的线，因此信号能传输更远）。

USB 不仅提供通信，还提供电源（电量取决于 USB 版本）。这就是为什么消费者可以通过将手机或相机插入电脑的 USB 端口来给它们充电。

与以太网一样，USB 交互通常复杂到需要一个操作系统（或一个远超简单驱动程序的 USB 协议栈）来处理。此外，USB 应用通常实现全部或大部分 OSI 层（参见"通信的分层模型（OSI）"）。

考虑其他协议

我希望你看到了不同串行协议的共同点。没有必要记住什么是什么。当你拿到外设的数据手册时，它会告诉你它需要什么，你的处理器会告诉你如何实现（如果没有，Wikipedia 可能会给你位敲打驱动程序的伪代码）。目标是思考什么使一个协议容易或难以实现。一些要点： • 你需要实现的层越多，实现就越复杂。许多协议不完全符合 OSI 模型，但了解这个框架对于估算仍然有用。 • 点对点比需要地址的网络更容易。 • 半双工比全双工更难，因为你必须切换通信方向。 • 同步比异步更容易，因为你确切知道何时会收到一个字节。 • 总线上有控制器（非对称）通常比弄清楚在没有人控制时谁可以说话更容易。 • 显式时钟比隐式时钟更容易。

串行通信

假设你需要实现一个智能卡的接触式接口。智能卡使用 ISO-7816，这是一种半双工、点对点、非对称协议，控制器提供时钟（范围在 1-5 MHz）。实现一个驱动程序会有多难？

基于这些信息，它看起来比 SPI 更复杂，但比 I2C 更简单。在你的计划估算中多留一点余量，因为该协议相对罕见，你可能找不到好的示例代码。现在，如果我告诉你它实现了四个或更多 OSI 层（虽然有所简化）呢？这应该将你的实现估算至少提高三倍。

那么更工业化的协议呢，比如 RS-485？它设计用于长距离传输，可以是全双工或半双工。当它是全双工时，是异步的。时钟是隐式的（100 kHz-10 MHz），只指定了物理层和数据链路层。通常有一个总线控制器，但这不是必需的。仅凭这些信息，实现该协议的难度听起来像是 RS-232 和 I2C 之间的交叉。

如果你能找到不同协议之间的共同点，那么一旦你写过类似的东西，在实现新东西时你就会知道该期待什么。

你需要从配置开始。首先，按照参考手册说的设置 I/O，使 SPI 子系统能工作。然后，按照 ADC 的要求设置 SPI 子系统。以下是配置步骤： 1. 设置 I/O 引脚，使片选、时钟和 MOSI 为输出。MISO 将为输入。 2. 设置 I/O 引脚归属 SPI 功能。 3. 根据 ADC 数据手册设置 SPI 配置：串行时钟速率、时钟极性（CPOL）和时钟相位（CPHA）、数据帧长度等。

最初，在电路板启动或原型测试期间，你可能会轮询传感器，向它询问信息以确保一切连接正确。然而，等待 SPI 通信完成是低效的，所以你可能需要一个中断来处理发送（和接收）SPI 字节。

4. 设置 SPI 中断，使其在发送缓冲区为空时触发。

即使有 SPI 中断来促进通信，你从 ADC 获得的数据也将是按需的。你需要设置 SPI 缓冲区来向 ADC 发送命令以启动转换（即收集数据）。然后你需要不停地发送 ADC 命令，询问它是否完成。当它完成时，你最终要设置 SPI 命令来读出数据。这是大量的来回交互；我们宁愿在 ADC 准备好发送数据时简单地获取数据。

但我们怎么知道数据何时就绪？ADC（或其他数字传感器）通常会有一个中断线来指示数据已准备好供你读取。一旦配置好，这根 I/O 线将在处理器上引起中断。虽然它可能作为通用 I/O 中断来实现，但在谈论传感器时，我们称之为数据就绪中断。

数据就绪中断将启动 SPI 交互，请求 ADC 发送数据。在中断中（或基于主循环中的事件标志），代码将： 1. 用要发送到 ADC 的信息填充发送缓冲区。这可能包括发送给 ADC 的命令，包括请求数据和启动下一次转换。

如有 FIFO 请使用 FIFO

与数字传感器通信的最慢方式通常是位敲打驱动程序。这是只有在万不得已时才用的选项。下一个最快的方式是使用处理器的通信机制，比如集成的 SPI 或 I2C 外设总线，每次中断传输或接收一个字节。

实践中的通信

如果硬件支持 FIFO（先进先出）队列，系统可以运行得更快。FIFO 提供了一个小型缓冲区，使数据在你必须处理之前可以积累一些。FIFO 队列可能是处理器的一部分，也可能是数字传感器的一部分（或两者都有，但不要同时使用两者）。

使用 FIFO 相当简单。要发送数据，写入发送保持寄存器（THR, Transmit Holding Register）。向该地址写入数据会将数据送入发送 FIFO。数据将在到达 FIFO 队列末尾且发送器可用时被发送出去。与环形缓冲区不同，这里不需要处理指针；你只需写入 THR 来填充 FIFO，数据最终会到达引脚。在外设流式输出其 FIFO 中存储的数据时，处理器可以做其他事情。

这些系统通常同时具有发送和接收 FIFO。要从接收 FIFO 获取数据，先检查确认有数据可用（使用状态寄存器），然后读取接收缓冲寄存器（RBR, Receive Buffer Register）以获取 FIFO 中最旧的数据。发送和接收寄存器（THR 和 RBR）可以是同一个寄存器，根据你写入还是读取来切换角色。

处理器 FIFO 使用一组标志向软件发送信号。状态标志通常包括：满、空、半满和半空。（如果你觉得 FIFO 有乐观/悲观问题，通常接收缓冲用半满信号，发送缓冲用半空信号。）这些电平可以用来中断处理器。

有些处理器允许你设置特定的中断触发级别。为获得最大吞吐量，需要确定处理器到达中断所需的时间（中断延迟）以及在这段时间内可以发送多少数据。例如，假设你想在 SPI 总线上保持稳定的数据流。如果你以 10 MHz 运行 SPI，且响应中断最多需要 3 微秒，那么你需要在 FIFO 还剩 4 字节时触发中断（10 MHz 时钟 → 1.25 MB/s → 0.8 μs/字节，3 微秒延迟 / 0.8 μs/字节 → 3.75 字节）。

发送中断通常用可用数据填充 FIFO。接收 FIFO 中断则排空所有数据，将其放到软件可以使用的地方（通常是环形缓冲区中）。目标是平衡触发级别，以便用最少的中断维持恒定的数据流。

第7章：与外设通信

你的处理器手册（或元件数据手册）会更详细地描述如何配置 FIFO。FIFO 通常是 8 或 16 字节深。但如果你的 FIFO 深度不那么受限呢？如果你的 FIFO 更像环形缓冲区，可以使用任意所需的 RAM 呢？

直接存储器访问（DMA）更快 支持直接存储器访问（DMA, Direct Memory Access）的处理器能够传输的数据量远超仅实现 FIFO 的处理器。

没有 DMA 时，处理器必须读取每一块数据并将其存储到内存中。对于每个传输的字节，从外设读取数据并将其存储到缓冲区时都有软件开销。DMA 绕过处理器，无需运行软件即可传输数据。

要使用 DMA，你给处理器一个指针和要读取（或写入）的字节数。接收时，处理器将数据从外设读入指定的内存，直到达到字节计数，此时它会中断软件。类似地，发送时，处理器将数据从缓冲区移动到外设，在计数完成时中断。

DMA 非常像有另一个线程替你处理数据。运行时非常方便，但设置起来可能很麻烦。请查阅处理器手册中的 DMA 寄存器：发送指针寄存器（写入设备的目标缓冲区）、发送计数、接收指针寄存器和接收计数。如果你的数据是分块到达而非连续流，可以使用单通道 DMA 控制器。如果数据是连续流，你可能需要将数据从 DMA 控制器复制到另一个位置，以便软件有时间处理它。

为了避免复制（这是对处理周期和 RAM 资源的低效使用），许多 DMA 实现可以在两个缓冲区之间交替。这允许软件使用一个缓冲区，而处理器将外设数据传输到（或传输自）另一个缓冲区。这种双缓冲、来回切换的方式称为乒乓缓冲（ping-pong buffer）。

DMA 用于具有极高吞吐量的外设。它也用于多核处理器中核间通信。如果你知道自己将接收多少字节（或者你要发送一个数据块而不是零散数据），DMA 是减少处理器开销的好方法，让你的处理器看起来比实际更快。

外部 ADC 示例：SPI 和 DMA

最慢的实现是位脉冲（bit-bang）SPI 驱动程序。次快的实现是硬件支持的接口。当你的处理器数据手册写着类似：

一个串行外设接口（SPI）—— 8 到 16 位可编程数据长度，四个外部外设片选

这就表示有内置 SPI。你可以将其配置为 1 MHz 运行（有时不太精确，因为这取决于处理器时钟和分频器的用法，但通常可以足够接近）。然后需要将其配置为每交换一个字节就触发中断，即每 8 μs 或 125 kHz（1 MHz / 8 位）。

在该中断中，你需要从接收寄存器获取字节并放入某种缓冲区。你还需要将下一个字节放入发送寄存器。中断不仅比位脉冲方案更短，而且中断次数也少得多。

当然，如果你的 FIFO 是 16 字节深，你只需要以 7.8 kHz（125 kHz / 16）的频率中断。嗯，如果你在 FIFO 完全满时中断的话可以。但这意味着如果你的中断没有在 8 μs 内（下一个字节进来之前）开始清空 FIFO，通信就会落后。

为了给你更大的余地，在 FIFO 半满时中断。这会给你更频繁的中断速率 15.6 kHz，但在通信落后之前有更多可用时间（64 μs）。

每次中断时，你需要将接收 FIFO 中的字节移动到另一块 RAM，并将发送字节移入该 FIFO。

现在来看 DMA。如果你的目标是最大化吞吐量，将 RAM 分为一小块用于局部变量和一大块用于乒乓缓冲。如果你有 32 KB 的 RAM，可以保留 2 KB 用于变量，并拥有两个各 15 KB 的乒乓缓冲区。这意味着你每秒只会收到八次中断，留下充足的时间进行实际处理。

表 7-2 仅比较了中断开销的处理差异（假设每个中断只有 10 个周期的开销，这是非常小的量）。我没有使用巨大的 DMA 缓冲区，而是给它一个合理的 512 字节来工作。注意，要实现位脉冲方案，你需要一个比同等 DMA 方案快 16,000 倍以上的处理器。这还仅仅是开销！位脉冲驱动程序比 DMA 中断更复杂，后者只需要切换指针并设置一个标志，让处理在已满的缓冲区上进行即可。

环形缓冲区

我之前提到 FIFO 像环形缓冲区，是因为我希望你之前听说过环形缓冲区。然而，在嵌入式系统中，你可能需要实际实现一个针对自己特定需求设计的环形缓冲区。让我多解释一下什么是环形缓冲区。

环形缓冲区是数据驱动系统中的关键实现策略。与第 5 章提到的后进先出（LIFO）栈不同，环形缓冲区是先进先出（FIFO）的。

数据生产者以某种速率将数据放入环形缓冲区。消费者以相同的平均速率从缓冲区取出数据。然而，消费者可以成块取出数据，而生产者以细碎方式放入数据。这让处理器在数据积累到算法所需的大小时可以做其他事情。（反过来也可以，生产者将一大块数据放入环形缓冲区，以稳定速率读取出来供给系统的另一部分。）

环形缓冲区需要跟踪一块内存、其长度、下一个元素写入的位置（写或起始）以及下一个元素读取的位置（读或结束）。参见图 7-6。注意，当读指针在写指针之前时，理解环形缓冲区更容易。这对所有人都成立；大多数常见的环形缓冲区错误发生在读写指针交叉时，即使软件有一半时间都处于这种状态。

当缓冲区为空时，读指针等于写指针。这很容易检查。然而，问题在于当缓冲区满时，读指针也等于写指针。

一种选择是当写指针距离读指针只差一个位置时认为缓冲区满。这很容易理解和实现，尽管会浪费一个元素的内存。另一种可能的方案是增加一个变量来跟踪长度，让入队函数递增长度，出队函数递减长度。现在你用变量换取了环形缓冲区中的一个位置。根据缓冲区中元素的大小，这可能是值得的。

你已经了解无符号二进制数（回顾第 87 页的"二进制与十六进制数学"）。第 114 页的"一个数需要多少位？"展示了 8 位或 16 位变量中能容纳的最大数，其中有符号数总是无符号数的一半，因为符号占用了一位。有几种用一位编码符号的方法；考虑一下我们在十进制中如何将符号放在数值左边来表示。在二进制中的一种做法是让符号为最左边位（最高有效位），而其他位编码数值：

注意，这里同时有 0 和 -0。许多编码都有这个问题。这有点奇怪，也有点低效。

空缓冲区将返回长度零。满缓冲区的长度为 (cb->size-1)。记住这一点，写入入队函数就相当简单了：

```c enum eError CBWrite(struct sCircularBuffer *cb, tElement data){ if (CBLengthData(cb) == (cb->size-1)) { return eErrorBufferFull;} cb->buf[cb->write] = data; cb->write = (cb->write + 1) & (cb->size - 1); // 必须是原子操作 return eSuccess; } ```

write 变量的修改需要是单条指令。但只有 write 变量的设置需要是原子的；准备工作（(write+1) 和 (size-1)）可以是多条指令。这些变量声明为 uint16_t，所以如果此代码在 16 位处理器上运行，write 变量的设置将是原子的（但对于 8 位处理器则不会；在 32 位处理器中，通常 uint16_t 的写入指令是单次操作，但不总是如此）。

还要注意，环形缓冲区拒绝会溢出缓冲区的数据。这回到了你希望系统如何失败的问题。你是想拒绝新数据，像这段代码那样？还是想丢弃一些旧数据为新数据腾出空间？你落后时的策略是什么？目前我采用报错方式，但你确实有选项可以考虑。

从缓冲区取出数据是类似的，但处理的是读偏移量而非写偏移量：

```c enum eError CBRead(struct sCircularBuffer *cb, tElement *data){ if (CBLengthData(cb) == 0) { return eErrorBufferEmpty;} *data = cb->buf[cb->read]; cb->read = (cb->read + 1) & ( cb->size - 1); return eSuccess; } ```

如果你不将缓冲区大小约束为 2 的幂，你需要使用额外的检查或取模运算来使指针回绕。取模运算（如除法）是相对较慢的操作，不是你希望在中断中做的事情。第 12 章会讨论嵌入式处理器上哪些数学运算是快还是慢。

注意，数据元素从缓冲区被复制到另一个位置。一般来说，复制内存对你的嵌入式系统不是一个好的用法，因为复制操作会消耗有限的处理周期，而拥有相同信息的两个副本会消耗有限的内存。为什么不直接把数据留在原处呢？

面试问题：选择处理器

你会如何为我们的下一代平台选择处理器？

这个问题是多方面的，首先是对面试者倾听能力的基本检查。他们知道我们做什么吗？他们对公司足够感兴趣以至于花时间做研究了吗？在我唠叨当前系统时他们是否清醒？

从那里开始，问题转向检查他们的设计技能和经验水平。我希望候选人知道该问哪些问题（当前平台的瓶颈是什么，我们是如何识别它们的？）。他们应该有具体的问题，关于处理类型和系统带宽需求，以帮助他们更好地理解问题。

大多数公司不想在功能集上倒退，所以从比之前设计更多的处理能力、更多的 RAM 和更多的代码空间出发相对安全。然而，我希望候选人检查这些假设。理想情况下，在我们讨论这些时，候选人应该描述减轻处理器负担的方法（外设通常占用不成比例的处理器开销）。

一个好的候选人还会考虑新平台的根本目标（即，我们为什么要寻找新平台？）。具有产品视野的候选人通常比视野受限的人更合适。为此，我希望他们询问产量和成本的目标。优秀的候选人还会询问需求是否预计在开发周期中发生重大变化，帮助他们确定是想要通用处理器还是可以选择非常特定的处理器。

我希望候选人讨论使用流行器件的优势（被编译器、调试器、工具链甚至 RTOS 广泛支持的器件）。听到他们考虑交货周期和停产预期也很好（提示：不要在即将淘汰的芯片上启动新平台）。好的候选人也会提到让新处理器位于一个处理器系列中间的目标，以便未来平台使用（以及可能使用功能较少器件来降低成本）。

处理器选择是困难的，因为许多因素都会影响决策。我不期望有人来面试一天就给出新处理器的建议。大多数人不会在脑海中记住各个微处理器供应商的处理器产品线。如果他们立刻给出具体的建议，我将其视为他们一直在从事的工作的指示。那时，我倾向于问他们为什么认为这对我们的特定产品是一条好的路径。目标是让他们告诉我他们会如何选择，而不是实际的选择。在面试中，人们面对问题的方法远比他们生成的解决方案更有趣。
