输入、输出和定时器

输入、输出和定时器构成了嵌入式系统几乎所有功能的基础。即使是用于与其它组件通信的通信方法，也是由它们构成的（参见第7章的位脉冲（bit-bang）驱动程序）。在本章中，我将带你走过一个产品开发的示例。目标会不断变化，所以会感觉像真实生活一样。这也让我们有机会探索如何从一个简单的闪烁灯系统，发展到按钮去抖动（debouncing）和LED调光。在这个过程中，我们将看到很多关于定时器的内容，以及它们如何远不止于测量时间。

不过，在我们开始征服世界之前——呃，我是说产品开发之前——你需要了解一些关于寄存器的知识，这是从软件到处理器的接口。

操作寄存器

要对I/O线做任何操作，我们需要与相应的寄存器通信。如"你的处理器是一种语言"（第56页）中所述，你可以将寄存器视为硬件的API。寄存器在芯片的用户手册中有详细描述，它们有各种形式，用于配置处理器和控制外设。它们是内存映射（memory-mapped）的，因此你可以通过写入特定地址来修改某个寄存器。通常，寄存器中的每一位（bit）都有特定的含义，这意味着我们需要开始使用二进制数来查看特定位的值。

二进制和十六进制数学

熟悉基本的二进制和十六进制（hex）数学将使你的嵌入式系统职业生涯更加愉快。当你只需要修改一两个位时，对单个位进行移位操作是很方便的。但如果你需要修改整个变量，十六进制就派上用场了，因为十六进制中的每一位数字对应二进制中的一个半字节（nibble，即四个位）（参见表4-1）。（没错，nibble当然是byte的一半。嵌入式领域的人很喜欢这种双关语。）

请注意，用四个位（一个十六进制数字）你可以表示16个数字，但你无法表示数字16本身。嵌入式系统中的许多东西都是从零开始的（zero-based），包括地址，因此它们与二进制或十六进制数字映射得很好。

一个字节（byte）是两个半字节（nibble），左边的半字节比右边的半字节向左移了四个位置。所以0x80就是(0x8 << 4)。

一个16位字（word）由两个字节组成。我们可以通过将最高有效字节向上移8位，然后加上低字节来得到它： 0x1234 = (0x12 << 8) + (0x34)

一个32位字在十六进制中是8个字符长，但在十进制中是10个字符长。虽然这种紧凑的表示法可以使调试输出更有用，但我们使用十六进制的真正原因是为了让二进制更容易处理。

由于内存通常以十六进制查看，一些值被用来识别内存中的异常。特别地，你可能会看到（并且使用）0xDEADBEEF或0xDEADC0DE作为指示符（它们在十六进制中比在十进制中容易记得多）。另外两个重要的字节是0xAA和0x55。因为这两个数字中的位是交替的，它们在示波器上很容易看到，当你需要看到数值中有大量变化时，它们很适合用于测试。

位操作 当你与寄存器打交道时，你需要从位的层面思考问题。通常，你会打开或关闭特定的位。如果你从未使用过位操作，现在正是学习的时候。逻辑运算符中，&&通常表示AND，!表示NOT，||表示OR，这些操作基于一个理念：任何为零的值都是假（false），任何非零的值都是真（true）。

测试、置位、清除和翻转

十六进制和位操作只是与寄存器交互的前奏。如果你想判断某个位是否被置位，你需要将该位与寄存器进行按位AND：

test = register & bit;

test = register & (1 << 3); // 检查寄存器中的第3位

test = register & 0x08;

// 相同，不同的语法

注意，test变量要么等于零（该位在寄存器中未被置位），要么等于0x08（该位被置位）。它不是true和false，尽管你可以在普通的条件语句中使用它，因为这些语句只检查零还是非零。

如果你想置位寄存器中的某一位，用OR将其与寄存器运算：

register = register | bit;

register = register | (1 << 3); // 打开寄存器中的第3位

register |= 0x08;

// 相同，不同的语法

清除某一位则要复杂得多，因为你希望保持寄存器中的其它位不变。典型的策略是使用按位NOT（~）将我们想要清除的位取反。然后将取反后的值与寄存器进行AND运算。这样，其它位保持不变：

register = register & ~bit;

register = register & ~(1 << 3); // 关闭寄存器中的第3位

register &= ~0x08;

// 相同，不同的语法

如果你想翻转某一位，你可以检查它的值，然后根据需要置位或清除。例如：

test = register & bit; if (test) {

register = register & ~bit; // 该位被置位，需要清除它

} else {

register = register | bit; // 该位未被置位，需要置位它

}

然而，还有一种使用XOR运算来翻转位的方法：

register = register ^ bit; register = register ^ (1 << 3);

如果寄存器中的0x08位被置位，XOR将看到两个1，并为该位输出零。如果寄存器中没有该位被置位，XOR将看到一个1和一个0，为该位输出一个1。寄存器中的其它位不会改变，因为只有第二个输入中的单个位被置位，其它位都是零。

复习到此为止。你需要了解这些操作才能使用寄存器。如果你对此还不熟悉，本章末尾提供了帮助你学习更多知识或进行练习的资源。

翻转输出 市场部带着一个产品创意来找你。当你拨开迷雾看清本质时，你意识到他们需要的只是一个闪烁的灯。

大多数处理器都有一些引脚，其数字状态可以被软件读取（输入）或设置（输出）。这些引脚被称为I/O引脚、通用I/O（GPIO）、数字I/O（DIO），偶尔也会被称为通用I/O（GIO）。基本用例通常很直接，至少当连接了LED时：

1. 初始化引脚为输出（作为I/O引脚，它可以是输入或输出）。 2. 当你想让LED亮时，将引脚置为高电平。当你想让LED灭时，将引脚置为低电平。（虽然LED也可以连接为当引脚为低电平时亮，但本示例将避免反向逻辑。）

在本章中，我将给你提供来自三份不同用户手册的示例，让你了解在你的处理器文档中应该期待什么样的内容。Microchip的ATtiny AVR微控制器手册描述了一款8位微控制器，具有丰富的外设。TI的MSP430x2xx用户指南描述了一款16位RISC处理器，设计目标是超低功耗。STMicroelectronics的STM32F103xx参考手册描述了一款32位Arm Cortex微控制器。你不需要这些文档也能跟上内容，但我想你可能会想知道这些示例是基于哪些处理器的。

将引脚设置为输出

回到市场部要你翻转LED的请求，大多数I/O引脚可以是输入也可以是输出。你需要设置的第一个寄存器将控制引脚的方向，使其成为输出。首先，确定你要更改的是哪个引脚。要修改引脚，你需要知道引脚名称（例如"I/O引脚2"），而不是它在处理器上的编号（例如引脚12）。名称通常在原理图中位于处理器内部，而引脚编号则在芯片封装的外部（如图4-2所示）。

图4-2. 带有一个LED连接的处理器原理图

引脚名称中可能包含多个数字，表示一个端口（port或bank）以及该端口中的一个引脚。（端口也可能是字母而不是数字。）在图中，LED连接到处理器引脚10，其名称为"SCLK/IO1_2"。此引脚在SPI端口（记住，这是一种通信方式，我们将在第7章中讨论）和I/O子系统（IO1_2）之间共享。用户手册会告诉你该引脚默认是I/O还是SPI引脚（以及如何在它们之间切换）。

可能需要另一个寄存器来指示引脚的用途。大多数供应商在引脚的交叉引用方面做得很好，但如果引脚在外设之间共享，你可能需要查看外设部分以关闭不需要的功能。在我们的示例中，我们假设该引脚默认是I/O。

在I/O子系统中，它是第一个bank（1）的第二个引脚（2）。我们需要记住这一点，并确保该引脚用作I/O引脚而不是SPI引脚。你的处理器用户手册会描述更多内容。查找标题为"I/O配置"、"数字I/O简介"或"I/O端口"的章节。如果你找不到名称，可以查找"方向"（direction）这个词，它通常用于描述你想要引脚作为输入还是输出。

一旦你在手册中找到了寄存器，你就可以确定需要在方向寄存器中置位还是清除某个位。在大多数情况下，你需要置位该位来使引脚成为输出。你可以确定地址并将结果硬编码：

*((int*)0x0070C1) |= (1 << 2);

但是，请不要这样做。

处理器或编译器供应商几乎总是会提供一个头文件或硬件抽象层（HAL，它包含一个头文件），隐藏芯片的内存映射，让你可以将寄存器当作全局变量来处理。如果供应商没有给你头文件，那就自己做一个，这样你的代码看起来更像是下面这几行：

STM32F103处理器

GPIOA->CRL |= 1 << 2; // 将IOA_2设置为输出

MSP430处理器

P1DIR |= BIT2; // 将IO1_2设置为输出

ATtiny处理器

DDRB |= 0x4; // 将IOB_2设置为输出

请注意，每种处理器的寄存器名称不同，但每行代码的效果是相同的。每种处理器设置字节（或字）中第二位的方式有不同的选项。

在这些示例中，代码都是读取当前寄存器的值，修改它，然后将结果写回寄存器。这种读-修改-写（read-modify-write）周期需要以原子（atomic）块的方式执行，这意味着它们需要在没有中断或任何其它处理插入在中间步骤的情况下完成。如果你读取了值，修改了它，然后在写回寄存器之前做了一些其它事情，你就冒着寄存器已经改变而你正在写入的值已经过时的风险。寄存器的修改会改变目标位，但也可能产生意想不到的后果。

点亮LED

下一步是点亮LED。同样，我们需要在用户手册中找到相应的寄存器：

STM32F103处理器

GPIOA->ODR |= (1 << 2); // IOA_2高电平

MSP430处理器

P1OUT |= BIT2; // IO1_2高电平

ATtiny处理器

PORTB |= 0x4; // IOB_2高电平

处理器供应商提供的GPIO硬件抽象层头文件展示了原始地址是如何被一些编程便利性所掩盖的。在STM32F103x6中，I/O寄存器通过一个结构体在某个地址被访问（我已经重新组织并简化了该文件）：

typedef struct { __IO uint32_t CRL; // 端口配置（低） __IO uint32_t CRH; // 端口配置（高）

__IO uint32_t IDR; // 输入数据寄存器

__IO uint32_t ODR; // 输出数据寄存器

__IO uint32_t BSRR; // 位置位/复位寄存器

__IO uint32_t BRR; // 位复位寄存器

__IO uint32_t LCKR; // 端口配置锁定

} GPIO_TypeDef; #define PERIPH_BASE 0x40000000UL #define APB2PERIPH_BASE (PERIPH_BASE + 0x00010000UL) #define GPIOA_BASE (APB2PERIPH_BASE + 0x00000800UL) #define GPIOA ((GPIO_TypeDef *)GPIOA_BASE)

这个头文件描述了许多我们还没有看过的寄存器。这些也在用户手册的相应章节中，有更多的解释。我更喜欢通过结构体来访问寄存器，因为它将相关功能组织在一起，通常可以让你互换地使用端口。

一旦LED亮了，我们还需要把它关掉。你只需要清除相同的位，如"测试、置位、清除和翻转"（第91页）中所示：

STM32F103处理器

GPIOA->ODR &= ~(1 << 2); // IO1_2低电平

MSP430 processor

P1OUT &= ~(BIT2);

// IO1_2 置低

ATtiny processor

PORTB &= ~0x4;

// IOB_2 置低

重复循环

为你的处理器编写好代码后，你应该编译、烧录并测试它。你可能需要调整延时循环的时间，让 LED 灯看起来合适。延时大约需要数万个处理器周期，否则 LED 灯会闪烁得太快，肉眼无法察觉。

故障排查 如果你搭建了 JTAG 等调试系统，找出 LED 灯不亮的原因应该会比较简单。否则，你可能需要采用排除法来排查。

首先，仔细复查你的数学运算。即使你对十六进制和位移操作非常熟悉，笔误总是有可能发生的。以我的经验来看，笔误是最难发现的错误，往往比内存损坏更难排查。检查你是否使用了原理图上正确的引脚。还要确保电路板已上电。（你可能会觉得这个建议很可笑，但这种情况出现的频率会让你惊讶！）

接下来，检查该引脚是否在不同外设之间共享。虽然我们说过该引脚默认为 I/O 功能，但如果遇到问题，请检查配置寄存器中是否有其他可选的复用功能被设置了。

在手册还打开的时候，确认引脚配置正确。如果 LED 灯没有响应，你需要阅读用户手册中的外设章节。不同处理器各不相同，请检查该引脚是否不需要额外的配置（例如电源控制输出），或者是否有默认开启的功能（不要意外将 GPIO 设为中断）。

大多数处理器默认将引脚设为 I/O 功能，因为这是用户（我们！）验证处理器连接正确的最简单方式。然而，尤其是对于低功耗处理器，你希望关闭所有未使用的子系统以避免功耗。（其他专用处理器可能有不同的默认功能。）用户手册会告诉你更多关于默认配置以及如何修改的信息。通常还有其他寄存器需要设置（或清除）某个位才能让引脚作为 I/O 使用。

有时需要配置时钟，才能使 I/O 子系统正常工作（或使延时函数足够慢，让你能看到闪烁效果）。如果仍有问题，请查找供应商的示例代码，并找出其中差异。

接下来，确保系统正在运行你的代码。你有没有其他方式验证正在运行的代码就是你编译的代码？如果你有调试串口，可以尝试递增版本号来验证代码是否被正确加载。如果这还不行，请确保你的构建系统使用了正确的目标处理器。

让代码尽可能简单，以确认处理器正在运行处理 LED 灯的功能。消除所有非关键的外设初始化，以防系统在等待一个不存在的外部设备时被阻塞。关闭中断和断言，并确保看门狗已关闭（参见第 164 页的"看门狗"）。

许多微控制器的引脚灌电流能力比拉电流（提供电流）能力更强。因此，引脚连接到 LED 灯的阴极而非阳极的情况并不少见。在这种情况下，你通过写零而非写一来点亮 LED 灯。这称为反逻辑。请检查你的原理图，确认是否属于这种情况。

如果输出仍然不工作，考虑是否存在硬件相关问题。首先，再次确认 LED 灯连接到了你认定的那个芯片引脚。然后，如果可能的话，在多个电路板上运行你的软件，以排除装配缺陷。即使是硬件方面，问题也可能很简单（LED 灯装反是很容易发生的）。也可能是设计问题，例如处理器引脚无法提供足够电流来驱动 LED 灯；数据手册（或用户手册）可能会告诉你这一点。电路板上也可能有问题，例如元件损坏或连接断开。由于大多数处理器的引脚密度很高，引脚之间很容易短路。请寻求帮助，或拿出你的万用表（或示波器）。

将硬件与动作分离

市场部很喜欢你的第一个原型，不过稍后可能需要稍作调整。系统从原型板变成了 PCB。在此过程中，不知怎的引脚号变了（变成了 IO1_3）。两个系统都需要能够正常运行。

对于这个项目来说，修改代码极其简单，但对于更大的系统，引脚可能会因为引入新功能而被打乱。我们来看看如何让修改变得更简单。

板级头文件

使用板级头文件可以避免硬编码引脚。如果你有一个头文件，只需在那里修改一个值，而不是在代码中到处修改引用它的地方。头文件可能如下所示：

#define LED_SET_DIRECTION (P1DIR) #define LED_REGISTER (P1OUT) #define LED_BIT (1 << 3)

配置和闪烁 LED 灯的代码行可以做到与处理器无关：

LED_SET_DIRECTION |= LED_BIT; // 将 I/O 设为输出

LED_REGISTER |= LED_BIT; // 点亮 LED 灯

LED_REGISTER &= ~LED_BIT; // 熄灭 LED 灯

如果你有很多 I/O 线或需要其他寄存器，这样写可能会变得有些笨拙。如果能只给定端口号（1）和端口内位置（3），让代码自行推导，那就好了。代码可能会更复杂一些，但很可能节省时间（并减少错误）。为此，头文件会是这样的：

// ioMapping_v2.h #define LED_PORT 1 #define LED_PIN 3

如果我们想为不同电路板编译不同的版本，可以使用三个头文件。第一个是旧电路板的引脚分配（ioMapping_v1.h）。接下来，我们为新引脚分配创建一个（ioMapping_v2.h）。我们可以在主 .c 文件中包含所需的那一个，但这样就违背了减少修改代码的目标。如果我们让主文件始终包含一个通用的 ioMapping.h，就可以通过包含正确的头文件在主文件中切换版本：

// ioMapping.h

#if COMPILING_FOR_V1

#include "ioMapping_v1.h"

#elif COMPILING_FOR_V2

#include "ioMapping_v2.h"

#else

#error "No I/O map selected for the board. What is your target?"

#endif /* COMPILING_FOR_* */

使用板级头文件可以巩固你的开发流程，以应对未来的硬件变更。通过将板级特定信息与系统功能分离，你正在创建一个更松耦合、更灵活的代码库。

在 Excel 中管理 I/O 映射表是一种相当常见的方式，用于确保硬件和软件工程师在引脚定义上达成一致。借助一点创造性的脚本编写，你可以从 CSV 文件生成特定版本的 I/O 映射表，以确保引脚标识符与原理图上的保持一致。

I/O 处理代码

我们现在需要以通用的方式处理多个端口，而不是直接在代码中写入寄存器。到目前为止，我们需要将引脚初始化为输出、将引脚设为高电平以点亮 LED 灯、将引脚设为低电平以熄灭 LED 灯。奇怪的是，即使对于如此简单的接口，我们也有很多实现方式可以组合。

在实现中，初始化函数将引脚配置为输出（并在必要时将其设为 I/O 引脚而非外设功能）。对于多个引脚，你可能倾向于将所有初始化集中在一起，但这会破坏系统的模块化。

虽然代码会占用稍多的空间，但更好的做法是让每个子系统初始化其所需的 I/O。这样，如果你移除或重用一个模块，所有需要的东西都在一个地方。然而，我们见过一种不应该将接口分散到子系统中的情况：I/O 映射头文件，其中所有引脚集中在一起，以便与硬件的接口更容易沟通。

继续讨论 I/O 子系统接口，将一个引脚设为高电平和低电平可以用一个函数完成：IOWrite(port, pin, high/low)。或者，也可以拆分为两个函数：IOSet(port, pin) 和 IOClear(port, pin)。两种方法都可以。想象一下在这两种情况下我们的 main 函数会是什么样子。

目标是让 LED 灯翻转。如果使用 IOWrite，我们可以有一个在高电平和低电平之间切换的变量。在 IOSet 和 IOClear 的情况下，我们需要保存该变量，并在主循环中检查它来决定调用哪个函数。或者，我们可以将 IOSet 和 IOClear 隐藏在另一个名为 IOToggle 的函数中。在我们的硬件方面没有任何特别的约束，所以在这个例子中不需要考虑优化代码。然而，出于教育目的，请考虑我们通过这些潜在接口给自己提供了哪些选择。

IOWrite 选项在一个函数中完成所有操作，因此代码空间占用更少。然而，它有更多参数，因此占用更多栈空间（来自 RAM）。此外，它还必须保留一个状态变量（也需要 RAM）。

使用 IOSet/IOClear/IOToggle 选项，函数更多（代码空间占用更多），但参数更少，可能不需要变量（RAM 占用更少）。请注意，翻转函数在处理器周期方面并不比置位和清零函数更昂贵。

这种评估要求你从另一个维度来思考接口。第 11 章将详细介绍如何针对每个方面进行优化。在原型阶段，优化代码还为时过早，但考虑如何设计代码以便日后可以优化，永远不嫌早。

void main(void){ IOSetDir(LED_PORT, LED_PIN, OUTPUT); while (1) {

// 永远循环

IOToggle(LED_PORT, LED_PIN); DelayMs(DELAY_TIME); } }

外观模式（Facade Pattern） 可以想象，随着产品功能的扩展，我们的 I/O 接口将变得更加复杂。（目前我们只有一个输出引脚，所以已经简单到不能再简单了。）从长远来看，我们希望隐藏每个子系统的细节。有一种标准的软件设计模式叫做外观模式（facade），它为一段代码提供简化的接口。外观模式的目标是让软件库更易于使用。按照我在本书中一直使用的比喻——与处理器接口类似于与软件库打交道——使用外观模式来隐藏处理器和硬件的某些细节是合理的。

在第 21 页的"为变化而设计"中，我们看到了适配器模式，它是外观模式的一个更通用的版本。适配器模式充当两层之间的翻译，而外观模式则通过简化下层来实现这一点。如果你充当科学家和外星人之间的翻译，你可能会被要求翻译"x = y + 2，其中 y = 1"。如果你是适配器模式，你会原封不动地重述相同的信息。如果你是外观模式，你可能会说"x = 3"，因为这样更简单，而且这些细节对使用信息来说并不关键。

在子系统中隐藏细节是良好设计的重要组成部分。它使代码更具可读性，更易于测试。此外，调用代码不依赖子系统的内部实现，因此底层代码可以更改，同时保持外观不变。

对于我们的闪烁 LED 灯，一个外观模式会将 I/O 引脚的概念从调用代码中隐藏起来，通过创建一个 LED 子系统，如图 4-3 右侧所示。考虑到用户对 LED 子系统需要了解的东西很少，外观模式可以只用两个函数来实现：

LEDInit() 调用 LED 引脚对应的 I/O 初始化函数（替代 IOSetDir(…)）

LEDBlink() 使 LED 灯闪烁（替代 IOToggle(…)）

添加外观模式让你的代码在需求不可避免地变化时更容易扩展和修改。

市场部想要改变系统响应按钮的闪烁方式。现在，当按钮被按住时，系统应该完全停止闪烁。

许多处理器的 I/O 引脚有内部上拉电阻。当引脚为输出时，上拉不起作用。然而，当引脚为输入时，上拉给它一个确定的值（1），即使没有连接任何东西。上拉的存在和强度可能是可配置的，但这取决于你的处理器（可能还取决于具体引脚）。大多数处理器甚至有选项允许在引脚上使用内部下拉。在这种情况下，我们的开关本来可以连接到电源而不是地。

带有内部上拉的输入会消耗一点功耗，所以如果你的系统需要节省几微安的电流，你可能最终会禁用不需要的上拉（或下拉）。

你的处理器用户手册会描述引脚选项。基本设置步骤如下：

1. 将引脚添加到 I/O 映射头文件中。 2. 将其配置为输入。验证它不是另一个外设的一部分。 3. 显式配置上拉（如果需要）。

一旦将 I/O 引脚设置为输入，你需要添加一个函数来使用它——一个可以返回引脚状态为高（true）或低（false）的函数：

boolean IOGet(uint8_t port, uint8_t pin);

当按钮被按下时，它将连接到地。这个信号是低电平有效，意味着当按钮被主动按下时，信号为低电平。

为了保持系统细节的隐藏，我们希望创建一个按钮子系统，它可以使用我们的 I/O 处理模块。在 I/O 函数之上，我们可以再放置另一个外观，使得按钮子系统拥有简单的接口。

等等！这个词（中断）非常重要。我相信你以前听过它，我们很快会详细介绍（并在第 5 章中再次讨论）。在此之前，先看看如果使用中断来捕获和处理按钮按下，主循环可以变得多么简单：

中断代码（即 ISR，中断服务例程）调用关闭 LED 灯的函数。然而，这使得按钮和 LED 子系统相互依赖，以一种不明显的方式将系统耦合在一起。有时你必须这样做，才能使嵌入式系统足够快地处理事件。

第 5 章将更详细地描述如何以及何时使用中断。本章将继续仅从高层面对它们进行讨论。

瞬时按钮按下

市场部想要通过轻触按钮来测试不同的闪烁速率，而不是用按钮来停止 LED 灯。每次按下按钮，系统应将延时长度减少 50%（直到接近零，此时应恢复到初始延时）。

在上一个任务中，你只需检查按钮是否被按下。这一次，你需要知道按钮何时会被按下以及何时会被释放。理想情况下，我们希望开关信号看起来像图 4-6 的上半部分那样。如果是这样，我们可以让系统注意到信号的上升沿并在那里采取行动。

这可能是另一个中断可以帮助我们的领域：捕获用户输入，使主循环不必如此频繁地轮询 I/O 引脚。如果使用一个全局变量来获知按钮按下，主循环会变得非常直观：

用户按下按钮时中断：

设置全局变量 button_pressed = true

loop: 如果全局变量 button_pressed 为真， 设置延时周期（重置或减半）

设置全局变量 button_pressed = false

关闭 LED 灯

如果经过了足够的时间，

翻转 LED 灯

清零经过的时间

许多处理器的输入引脚可以配置为在引脚信号处于特定电平时（高或低）或发生变化时（上升沿或下降沿）产生中断。如果按钮信号看起来像图 4-6 顶部理想的按钮信号那样，你希望在哪里触发中断？在信号为低电平时中断可能会导致用户按住按钮时多次激活。我更喜欢在上升沿中断，这样当用户按下按钮时，直到他们释放按钮才会采取行动。

在这种情况下要准确检查全局变量，你需要使用 volatile 这个 C 语言关键字，也许你之前在 C 和 C++ 软件开发中从未需要过它。这个关键字告诉编译器，该变量或对象的值可能会意外改变，永远不应被优化掉。所有寄存器以及中断与普通代码之间共享的所有全局变量都应标记为 volatile。如果你的代码在没有优化时工作正常，而开启优化后却失败，请检查相应的全局变量和寄存器是否标记为 volatile。

配置中断 配置引脚以触发中断通常与将引脚配置为输入是分开的。虽然两者都属于初始化步骤，但我们希望将中断配置与现有的初始化函数分开。这样，你可以将中断配置的复杂性保留给需要它的引脚（详见第 5 章）。

配置引脚以中断处理器为我们的 I/O 子系统增加了三个函数：

IOConfigureInterrupt(port, pin, trigger type, trigger state) 将引脚配置为中断。当中断看到某种触发类型时（如边沿或电平），就会触发。对于边沿触发类型，中断可以在上升沿或下降沿发生。对于电平触发类型，中断可以在电平为高或低时发生。有些系统还提供一个回调参数，即当中断发生时调用的函数；其他系统则将回调硬编码为某个函数名，你需要将代码放在那里。

IOInterruptEnable(port, pin) 使能与引脚关联的中断。

IOInterruptDisable(port, pin) 禁能与引脚关联的中断。

如果中断不是按引脚分配的（可能是按端口组分配的），处理器可能为每个端口组设有一个通用 I/O 中断，在这种情况下，ISR 需要梳理出是哪个引脚引发了中断。这取决于你的处理器。如果每个 I/O 引脚都可以有自己的中断，模块之间就可以更加松耦合。

开关去抖动

许多按钮并不提供图 4-6 上半部分所示的干净信号。相反，它们看起来更像标有"有抖动的数字按钮信号"的波形。如果你对该信号进行中断，系统可能会在按钮按下开始和结束时因毛刺而浪费处理器周期。开关抖动可能是由机械效应或电气效应引起的。

图 4-6 还展示了按钮被按下时可能发生的模拟视图，信号只是缓慢生效。（实际情况可能要复杂得多，取决于抖动主要是由机械原因还是电气原因引起。）注意，模拟信号中有部分区域既不是高电平也不是低电平，而是介于两者之间。由于你的 I/O 线是数字信号，它无法表示这种不确定的值，可能会表现异常。一个充满边沿的数字信号会让代码以为每次用户操作产生了多次按下。结果会不一致且令用户沮丧。更糟的是，对此类信号进行中断可能导致处理器不稳定，所以我们还是回到轮询信号的方式。

图 4-6. 按钮信号的不同视图

去抖动是用于消除虚假边沿的技术。虽然可以在硬件或软件中实现，我们将着重讨论软件实现。关于硬件解决方案，请参阅 Jack Ganssle 关于去抖动的优秀网络文章（见第 123 页的"延伸阅读"）。

许多现代开关的不确定期非常短。开关也有数据手册；请查阅你的开关，了解制造商推荐的值。请注意，试图凭经验判断是否需要去抖动可能不够，因为不同批次的开关可能表现不同。

你仍然要寻找信号的上升沿，即用户释放按钮的时刻。为了避免上升沿和下降沿附近的杂波，你需要寻找一段相对较长的信号稳定期。这段时间的长短取决于你的开关以及你想多快响应用户。

要对开关进行去抖动，需要以比期望响应速度快几倍的周期对引脚进行多次读取（即采样）。当有多次连续一致的采样后，通知系统其余部分按钮状态已改变。参见图 4-6；目标是读取足够的次数，使不确定的逻辑电平不会导致虚假的按钮按下。

依赖注入 然而，我们可以超越状态变量，做到更加灵活。之前我们看到，将 I/O 引脚从电路板中抽象出来，使我们不必在电路板变更时重写代码。我们也可以使用抽象来处理动态变化（例如使用哪个 LED 灯）。为此，我们将使用一种称为依赖注入的技术。

之前，我们将 I/O 引脚隐藏在 LED 代码中（创建了一个仅依赖较低层的函数层次结构）。通过依赖注入，我们将移除这种依赖，将 I/O 处理器作为参数传递给 LED 初始化代码。I/O 处理器将知道更改哪个引脚以及如何更改，但 LED 代码只知道如何调用 I/O 处理器。参见图 4-7。

一个常用来解释依赖注入的例子将引擎与汽车联系起来。汽车（最终产品）依赖引擎来移动。汽车和引擎由制造商制造。虽然汽车不能选择安装哪个引擎，但制造商可以注入汽车可以使用的任何依赖选项来行驶（例如，800 马力的引擎或 20 马力的引擎）。

回溯到 LED 灯的例子，LED 代码就像汽车，依赖 I/O 引脚来工作，就像汽车依赖引擎一样。然而，LED 代码可以做得足够通用，避免依赖特定的 I/O 引脚。这允许 main 函数（我们的制造商）根据情况安装适当的 I/O 引脚，而不是在编译时硬编码依赖。这种技术允许你在运行时组合系统的工作方式。

在 C++ 或其他面向对象语言中，为了注入依赖，每当按钮被按下时，我们将一个新的 I/O 引脚处理器对象传递给 LED 灯。LED 模块永远不会知道它正在改变哪个引脚或如何改变。隐藏这些细节的变量在初始化时设置（但请记住这些是变量，会消耗 RAM 并使代码变得杂乱）。

在 C 语言中，通常使用函数指针结构体来达到同样的目的。

依赖注入是一种非常强大的技术，特别是如果你的 LED 模块要做更复杂的事情，例如输出摩尔斯电码。如果你传入你的 I/O 引脚处理器，你就可以在任何处理器上重用摩尔斯电码 LED 输出例程。此外，在测试期间，你的 I/O 引脚处理器可以打印出 LED 模块对其进行的每次调用，而不是（或除了）改变输出引脚。

然而，汽车引擎的例子说明了依赖注入的一个主要问题：复杂性。当你只需要更换引擎时，它工作得很好。但一旦你开始注入车轮、转向柱、座椅套、变速箱、仪表盘和车身，汽车模块就变得相当复杂了，自身几乎没有内在的实用价值。

依赖注入的目标是允许灵活性。这与外观模式的目标相反，外观模式旨在降低复杂性。在嵌入式系统中，依赖注入会占用更多的 RAM 和额外的处理器周期。外观模式几乎总是会占用更多的代码空间。你需要考虑系统的需求和资源，以找到一个合理的平衡点。

使用定时器

使用按钮来改变闪烁速度是有帮助的，但市场部发现闪烁速率引入了不确定性。市场部不想让 LED 灯的速度减半，而是希望通过按钮在一系列精确的闪烁速率之间循环：每秒 6.5 次（Hz）、8.5 Hz 和 10 Hz。

这个需求看似简单，但这是第一次我们需要处理时间精度的问题。之前，系统可以在方便的时候处理按钮和翻转 LED 灯。现在，系统需要实时处理 LED 灯。你能达到多"精确"取决于系统的参数，主要是处理器输入时钟的准确度和精密度。我们将先使用处理器上的定时器使其比之前更精确，然后看看市场部是否能接受。

定时器的各个部分

原则上，定时器是一个简单的计数器，通过累积一定数量的时钟节拍来测量时间。主时钟的确定性越高，定时器就能越精确。定时器独立于软件执行运行，在后台工作，完全不拖慢代码。从技术上讲，它们在微控制器的硅门电路中运行。

要设置定时器的频率，你需要确定时钟输入。这可能是你的处理器时钟（即系统时钟或主时钟），也可能是来自另一个子系统的不同时钟（例如，许多处理器有外设时钟）。

系统统计 当嵌入式系统工程师与其他工程师谈论我们系统的统计数据时，我们倾向于使用一种简写形式，包括供应商、处理器（及其内核）、每条指令的位数以及系统时钟速度。在本章前面，我给出了来自 STM32F103xx、MSP430 和 ATtiny 处理器系列的寄存器示例。使用这些处理器的系统可能具有如下统计数据：

- STM32F103（Cortex-M3），32 位，72 MHz - Texas Instruments MSP430 G2201，16 位，16 MHz - Atmel ATtiny45，8 位，4 MHz

最后一个数字是处理器时钟，描述了处理器理论上每秒可执行的指令数。如果内存访问跟不上，实际性能可能会更慢；或者如果你能利用处理器特性绕过开销，实际性能可能会更快。系统时钟与电路板上的振荡器（如果你有的话）不同。由于内部 PLL 电路的存在，你的处理器速度可能比板载振荡器快得多。PLL 代表锁相环，表示处理器可以将较慢的时钟（即慢速振荡器）倍频以获得更快的时钟（处理器时钟）。由于较慢的振荡器通常比较快的振荡器更便宜（且功耗更低），PLL 无处不在。

许多小型微控制器使用内部 RC 振荡器作为时钟源。虽然这些使硬件设计师的工作变得更简单，但它们的精度远不尽如人意。随着时间推移，可能会出现相当大的漂移，这可能导致通信和一些实时应用中的错误。

例如，ATtiny45 的最大处理器时钟为 4 MHz。我们希望 LED 灯能够以 10 Hz 的频率闪烁，但这意味着要以 20 Hz 的频率中断（中断打开，再次中断关闭）。这意味着我们需要 200,000 的分频。ATtiny45 是 8 位处理器；它有两个 8 位定时器和一个 16 位定时器。没有一个定时器能计数到那么高（参见第 111 页的侧栏"系统统计"）。然而，芯片设计者意识到了这个问题，并给了我们另一个工具：预分频器寄存器，它对时钟进行分频，使计数器以较慢的速度递增。

许多定时器是从零开始的，而不是从一开始，因此对于分频 2 的预分频器，你在预分频器寄存器中写入 1。整个定时器这件事已经够复杂了，不用在上面的数学运算中纠结这点。请查看你的处理器手册，了解哪些定时器寄存器是从零开始的。

定时器是一组完全相同的脉冲，因此定时器信号是50%高电平和50%低电平（这被称为50%占空比）。在PWM中，脉冲的宽度根据情况而变化。因此PWM可以有不同的比率。100%占空比的PWM始终导通，就像输出引脚的高电平。而0%占空比表示引脚已被驱动（或下拉）为低电平。占空比代表信号的平均值，如图4-10中的虚线所示。

在20 Hz定时器下，这可能看起来像一系列非常快的闪烁，而不是一个变暗的LED。问题在于20 Hz定时器太慢了。你增加频率越多，LED看起来就越暗而不是闪烁。然而，更快的频率意味着更多的中断。

有一种方法可以在处理器中执行此过程。在上一节中，可配置的动作包括是否重置计数器以及如何设置引脚。许多定时器有多个比较寄存器，并允许每个比较寄存器有不同的动作。因此，PWM输出可以用两个比较寄存器来设置，一个控制开关频率，另一个控制占空比。

例如，图4-10底部显示了一个定时器向上计数并被重置。这代表了由比较寄存器设置的开关频率。我们将这个比较寄存器命名为A并设为100。当达到这个值时，定时器被重置，LED被打开。占空比由另一个寄存器（比较寄存器B，设为80）设置，它关闭LED但允许定时器继续计数。

哪些引脚可以作为PWM输出取决于你的处理器，尽管通常它们是可以用作定时器输出的引脚的一个子集。处理器用户手册中的PWM部分可能与定时器部分是分开的。此外，还有不同的PWM控制器配置，通常用于特定应用（电机通常对所需PWM类型很挑剔）。

对于我们的LED，一旦PWM设置完成，代码只需要在按下按钮时修改占空比。与定时器一样，main函数根本不直接控制LED。

尽管调暗LED是市场部要求的，但还有其他有趣的应用可以尝试。要实现一种呼吸灯效果，即LED渐亮渐暗，你需要以增量方式修改占空比。如果你有三色LED，你可以使用PWM控制将三种LED颜色设置为不同级别，提供一整套颜色选项。
